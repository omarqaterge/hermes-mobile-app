- **Web pictures in replies now wait for your tap, in every chat.** A reply can no longer load an image, video or sound from the web by itself: you see the site's name and "Tap to load" first, because a web address can carry out whatever the agent has read, and a page it reads could trick it into writing one. Until now this was true only in a chat that had read your phone data. Diagrams that name a picture or an address are shown as text instead of being drawn, and a reply's colours can no longer pull a picture from the web either. The app's own page also gets a basic security policy against embedded objects and redirected addresses. Pictures in cards still load by themselves unless the chat has read phone data. Checked with unit tests and a new browser check written for this change, but not run here (no packages could be installed) and not tried on a phone.
