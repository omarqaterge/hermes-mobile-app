### 3.15 Settings

**Source files:** `web/src/components/Settings.tsx` (`SettingsScreen`, the page components, `ModelPicker` (`noEffort` hides the reasoning pills), `setProfileModel`, `profileLabel`), `web/src/theme.ts`, `web/src/update.ts`, `web/src/releasenotes.ts`, `web/src/hermes-update.ts`, `web/src/hermes-settings.ts` and `web/src/components/HermesSettings.tsx` (the Hermux settings page), `web/src/settings-search.ts` and `web/src/flash.ts` (Settings search), `web/src/connectors.ts` and `web/src/components/Connectors.tsx` (the Connectors page); rows that live in other files are marked below (`AutoAccess.tsx` `DefaultAccessRow`, `Uninstall.tsx` `UninstallSection`, `Providers.tsx` `ProviderList`). Hermes validates and stores every write, exactly as Hermes Desktop would: the app only calls the dashboard's REST routes, scoped with `?profile=`.

**Opens from:** the ⚙ Settings tile in the drawer; the Bots sheet's "API keys & settings" (opens the API keys page for that bot). **Closes with:** Back arrow (a sub-page goes back to the Settings main page first; Android Back does the same). **Source:** `Settings.tsx` `SettingsScreen`.

The screen has one main page and nine sub-pages. The top-bar title is the page name: Settings, Appearance, Voice, Speech recognition (under Voice), Default models, Model providers, API keys, Connectors, Hermux settings, Advanced settings. Sub-pages that act on one bot (Model providers, API keys, Connectors, Hermux settings, Advanced settings) start on the open bot and show bot chips (the `ProfileChips` row, headed "Sign-ins for", "Keys for", "Connectors for" or "Settings for"); tapping a chip changes the target bot.

**Settings search.** The top of the main page has a search field ("Search settings", with a ✕ `set-search-clear` button (aria-label: Clear search) once something is typed). While it holds text the sections are replaced by a "Results · N" list, updated on every keystroke; "No settings match “…”" when nothing fits. Each result shows its title and where it lives ("Voice › Live mode · …"). Choosing one opens that page (`SettingsScreen` `pick`), then scrolls to the row or section heading with that title and flashes it for 2.5 s (the `.hit-flash` ring). Pages that fill in after a request are waited for, about 1.5 s. The list is `web/src/settings-search.ts`: `searchSettings(query)` (every typed word must appear in a title, text, place or search words; title matches first), a hand-kept list of the rows and sections in this file's pages (add a new setting there too), and the Hermux settings taken from `HERMES_SETTINGS`; `setKnownHermesKeys` is called by the Hermux settings page once loaded so options the running Hermes lacks drop out. `web/src/flash.ts` holds `findSettingsTarget` (finds a `.set-title` or `.set-heading` by its words and returns its row or section) and `flashElement` (centres and flashes it; no smooth scroll under reduced motion). Advanced settings and API keys keep their own search fields for their runtime lists.

**In-app update row** (`Settings.tsx` `UpdateRow`, `web/src/update.ts`): it asks GitHub once when the page opens (and not again within a minute, no polling): `GET https://api.github.com/repos/omarqaterge/hermes-mobile-app/releases/latest`. It compares the release tag with `appVersion()` (dotted numbers, a leading `v` ignored). The row changes with `phase`:
| Phase | Title | Sub text |
|---|---|---|
| checking | Check for updates | Checking… (row disabled) |
| uptodate | Check for updates | "You're on the latest version (x)", or "You have a, newer than the latest release (x)" |
| available | Update to x | "A newer version is ready. Tap to download and install" (gold icon) |
| downloading | Check for updates | "Downloading… N%" (disabled) |
| installing | Check for updates | "Confirm in the Android installer" (disabled) |
| permission | Update to x | The shell's message, e.g. the "install unknown apps" request; tap again after allowing |
| error | Check for updates | The reason: GitHub rate limit, "Can't reach GitHub. Check your connection.", "Version x has no app file yet.", "Updating works inside the Android app only." |
A tap in `available` or `permission` calls `startUpdate()`, which hands the release's `.apk` URL to the Android shell (`installUpdate` bridge call; the shell only accepts this project's GitHub release URLs), downloads it and opens the system installer, which asks the user to confirm. The shell reports progress by calling `window.hermesUpdate(state, percent, message)`. Any other tap forces a new check.

**What's new** (`Settings.tsx` `WhatsNewRow`, `web/src/releasenotes.ts`): when `checkForUpdate` finds a newer release it makes one more request, `GET https://api.github.com/repos/omarqaterge/hermes-mobile-app/contents/CHANGELOG.md?ref=<tag>` (raw), so the text is `CHANGELOG.md` as it is at that release's tag; it is not read again for the same version. `notesSince` keeps every `## vX.Y.Z (date)` section newer than `appVersion()` and not newer than the release (so versions skipped in between are listed too; `## Unreleased` never is), newest first, into the update state's `notes` (`ReleaseNotes`: version, date, text). The sheet "What's new" shows each version as a heading with its date and a bullet list with one short line per change (`headlines`: each bullet's bold headline, else its first sentence, cut at 120 characters), in the changelog's order, which puts the biggest changes first (7.5); a `###` heading in the section, such as the "Smaller changes and fixes" a release puts last, becomes a small heading over its own list (`.whats-new-group`). A **Details** button (`.whats-new-more`, then **Hide details**) shows the whole section rendered by `Markdown` (sanitised like replies); a section with no bullets is rendered that way at once. Under the versions the sheet has an "Update to <version>" button while the update can start (it calls `startUpdate()` and closes the sheet). If the changelog can't be read (offline, rate limit, no file) the row is simply not shown; the update row works as before. The row goes away once the app is up to date.

**Hermux agent row and the version check** (`Settings.tsx` `HermesRow`, `web/src/hermes-update.ts`): the app talks to a Hermes build it was written against (`__HERMES_TESTED__`, injected at build time). `checkHermes` reads `current_version` from `GET /api/hermes/update/check` (the update fields in that answer are ignored). `compat` compares the git short hash in both version strings: `same`, `newer`, `older` or `unknown`. On `newer` or `older` the row turns gold and says "Different from what this app was made for. Update the app (x)." (or "…If something breaks, update the app."), and a toast is shown once per differing build (the build string is remembered in `hm.hermesSeen`). There is no "update Hermes" button on purpose: Hermes updates ship with an app release, after the app has been adapted to them.

**The options** (key: control, limits):
- When a model fails: `agent.api_max_retries` (1–10), `fallback.min_switch_reset_seconds` (0–3600 s, 0 = always switch), `agent.auto_recovery_cycles` (0–20).
- Replies: `agent.max_turns` (1–5000 or no limit), `agent.run_budget_seconds` (30–86400 s or off), `agent.text_verbosity` (provider default, short, medium, long), `agent.image_input_mode` (automatic, always attach, always describe), `agent.verify_on_stop` (off, for coding = `auto`, always), `prompt_caching.cache_ttl` (5 minutes, 1 hour, automatic, off), `goals.max_turns` (1–500), `agent.clarify_timeout` (0–86400 s, 0 = no limit) and `approvals.timeout` (30–86400 s).

- Web and tools: `web.extract_char_limit` (1000–1000000), `web.cache_enabled`, `web.cache_ttl_minutes` (1–1440), `web.keyless_fallback`, `terminal.timeout` (10–86400 s), `tool_output.max_bytes` (1000–10000000), `browser.inactivity_timeout` (10–3600 s), `checkpoints.enabled`, `checkpoints.max_snapshots` (1–500), `checkpoints.retention_days` (1–3650), `tool_loop_guardrails.hard_stop_enabled`, `network.force_ipv4`.
- Safety and privacy: `security.redact_secrets`, `privacy.redact_pii`, `security.allow_private_urls`, `security.protected_instruction_files`, `approvals.denial_breaker_threshold` (0–50, 0 = off), `approvals.deny` (list), `security.website_blocklist.enabled`, `security.website_blocklist.domains` (list), `skills.write_approval`.
- Chats and housekeeping: `timezone` (text, checked against Hermes's list), `sessions.auto_prune`, `sessions.retention_days` (7–3650), `sessions.auto_archive`, `sessions.auto_archive_days` (1–365), `curator.enabled`, `curator.stale_after_days` and `curator.archive_after_days` (1–3650), `cron.catch_up_missed`, `cron.allow_agent_scheduling`, `cron.output_retention` (0–10000, 0 = keep all), `logging.level` (Debug, Info, Warning, Error).
