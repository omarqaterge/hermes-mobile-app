### 3.16 Bots

A bot is a Hermes profile. The screen works like Hermes Desktop's Profiles page. There is no channel or messaging-gateway UI here, on purpose.

**Opens from:** "Manage bots" in the bot sheet (the bot at the bottom of the side panel, 3.13). **Closes with:** Back (to the chat). **Source:** `web/src/components/Bots.tsx` `BotsScreen`.

**Layout, top to bottom:**
| Element | Looks like | Tap | States |
|---|---|---|---|
| ＋ (`aria-label` "New bot") | Top-bar button | Opens the "New bot" sheet | |
| Bot card | Avatar letter, the display name (and the bot's id in monospace when it differs), a line "Main bot" or the description ("No description"), a line with the model ("no model") | Opens the bot sheet | "No bots", error notice, loading |
| One bot so far | Only while there is a single bot: the empty state (`EmptyState`, 3.20) "One bot so far", "Each bot is its own Hermux, with its own model, memory, skills and keys. Make another for a different job." and the gold button "New bot" | Opens the "New bot" sheet, like the top-bar ＋ | |

**New bot sheet:** Name (forced to lower case, spaces become `-`, other characters dropped; must match letters/digits/`-`/`_`, 1–64 characters, shown red when invalid, hint "Lowercase letters, numbers, - and _."); "Start from" chips: Blank, or one chip per existing bot (the hint says what is copied: settings, keys, skills and SOUL.md, not chats or memory; Blank says "A fresh bot with the bundled skills."); "What is it for? (optional)"; "SOUL.md — personality (optional)". Cancel / Create (disabled without a valid name; "Creating…"). Create calls `POST /api/profiles` with `{ name, clone_from, description }`, then `PUT /api/profiles/<name>/soul` if a personality was typed, then `POST /profiles/link` (plugin route that links the Hermux plugin into the new profile, whose plugin folder starts empty; failure is ignored). Then the new bot's sheet opens.
**Bot sheet** (title = bot name): a Description field with Save (appears once edited; `PUT /api/profiles/<name>/description`), then Id, Model, Skills count, then the menu:
| Entry | What it does |
|---|---|
| 💬 Chat with <name> | Closes the screen, `switchProfile(name)`, then `startDraft()` |
| 🧩 Default model | Opens the model picker for this bot (3.15), via `setProfileModel`; the toast "New chats with <name> use <model>" has the button New chat (`toastNewChats`, 3.20) |
| (user icon) Personality (SOUL.md) | Sheet "SOUL.md · <name>" with a text area loaded from `GET /api/profiles/<name>/soul`; Back / Save (`PUT …/soul`, toast "Saved. New chats use it" with the button New chat) |
| 🔑 API keys & settings | Opens Settings with `screenProfile` set to this bot, which starts on the API keys page for it |
| ✎ Rename | Sheet "Rename <id>": field "New name"; `PATCH /api/profiles/<id>` with `{ new_name }`. The main bot keeps its id and only changes the name shown ("The main bot keeps its id; this changes the name shown."); other bots get their folder renamed (chats, memory and skills are kept). If the open bot is renamed the app switches to the new id |
| 🗑 Delete bot | Not shown for the main bot. A prompt "Delete “<id>”?" ("This deletes the bot and ALL its chats, memory, skills and keys. It cannot be undone. Type its name to confirm."); the red button "Delete bot" stays disabled until the typed text equals the id. If the bot is open the app first switches to `default`, then `DELETE /api/profiles/<id>` |

**Profiles in the rest of the app.** The side panel's bot sheet (3.13) and every "Bot" chip use the same list: `profiles.list` RPC (`loadProfiles`) fills the store's `profiles`; `profileLabel` prefers `display_name`, then `bot_title`, then the id. The open profile is kept in `hm.profile`.
**Data:** `GET /api/profiles`, `POST /api/profiles`, `PATCH /api/profiles/<id>`, `DELETE /api/profiles/<id>`, `GET` / `PUT /api/profiles/<id>/soul`, `PUT /api/profiles/<id>/description` (all without the profile scope), `POST /profiles/link`.
