### 3.3 Messages

The chat view draws `store.active.items`, an array of `ChatItem` (`web/src/store.ts`). `ItemView` (`web/src/components/ChatItems.tsx`) draws one item. The kinds:

| Item kind | Made from | Drawn as |
|---|---|---|
| `user` | A sent prompt, or a stored user row. | Right-aligned bubble (below). |
| `assistant` | Streamed `message.delta` / `reasoning.delta`, or a stored assistant row. | Reasoning block, Markdown reply, actions (below). |
| `tool` | `tool.generating`, `tool.start`, `tool.complete`, or a stored tool row. | Tool card (below). |
| `subagent` | `subagent.*` events; put back after their `delegate_task` call when a chat is reopened. | One line for the group (below). |
| `notice` | Stored system rows; steer, slash, review, background and compress results; send failures; model errors. | Coloured box with Markdown text. |

There is no separate item kind for approvals, images, files or errors. Approvals are a sheet (3.6). Images and files are parts of user messages (and of Markdown in replies). Errors are `notice` items with level `error`, or a tool card in the error state. Cards written by Hermes in a reply are Markdown code fences (3.9).

#### User message

`UserMsg`. A bubble with the text (web addresses are links, `Linked.tsx`). Leading lines that start with `>` (with or without the space after it) are drawn as quote blocks (`.msg-quote`: left border, dim text) above the rest, one block per quote (`splitQuote` in `web/src/quote.ts`); this also shows stored chats correctly after a reload. Edit still edits the full text, quotes included.

- **Attachments.** Photos sent from this phone show as thumbnails (tap: the Lightbox). Photos of a resumed chat show through `Media` from their path; if only a name is known, a chip "🖼 name". Files show as chips "📎 name".
- **Time.** Tapping the bubble (not a link, button, code, table, image, or selected text) toggles the send time under it: "14:05" for today, otherwise weekday, day, month and time.
- **Actions** (row under the bubble, drawn for every user message in the open chat, never in the read-only preview): Copy (copies the text) and Edit.
- **Edit** turns the bubble into an edit box: the text in a textarea that grows with its content, the attached files and photos as chips with ✕ (aria-label "Remove <name>") so they can be dropped from the edit, and Cancel / Send. Send is disabled while a reply runs or the text is empty. It calls `resendFrom` (below).

#### Assistant reply

`AssistantMsg`.

- **Reasoning block** (`Reasoning`): hidden when there is no reasoning text, and while the reply's turn is folded (`quiet`, below: the thought is part of the turn's line). While the reply streams without text yet it reads "Thinking…" with a small turning orb (`ThinkOrb`, still unless Animations is Full and it is the one thing that moves; 3.2 Agent motion) and a peek of the latest `**Heading**` in the thought, else its last sentence. Once finished it reads "Thought for 12s" (`.reasoning-title`, whole seconds by `wholeTime`) when the page watched the thought stream, else "Thought process", with a brain icon; while closed, the thought's first heading, else its first sentence (`.reasoning-line`, `thoughtLine` in `web/src/toolsay.ts`, at most 140 characters), follows on the same row after a "·", cut with an ellipsis where the row ends (left out of the button's accessible name). Tap to expand the full reasoning (links work). How long a thought took is measured in the page, since no stored record holds it: `trackThought` (`web/src/turnfold.ts`, called by the chat view whenever its items change) notes when the streaming reply's thought starts and when the reply's text starts or its part closes; `thoughtSecs` reads it by item id. Only the last item and the one open thought are looked at; at most 400 are kept, in memory only, so a chat opened from history shows "Thought process".
- **Text** (`Markdown`, see below), with a blinking caret while streaming. While streaming, Markdown skips language detection for unlabelled code blocks (it waits for the finished reply) and is drawn in parts ("A reply that arrives in pieces" below).
- **Warning line** "⚠ <warning>" when the turn ended with a warning.
- **Actions** (only when the reply is finished and is the last text segment of its turn; `hasActions` in `App.tsx`): Copy, Read aloud, Retry, Branch, and the turn stats.
  - **Copy** opens the picker "Copy reply": "Text only" (plain words, no formatting marks, via `plainText`) or "With formatting" (rendered HTML, with buttons, widgets and classes removed, copied through the `copyRich` bridge call so it pastes as headings, lists and tables into Docs, Gmail, Notes; if the message has no rendered HTML the raw Markdown text is copied).
  - **Read aloud** speaks the reply (`toggleSpeak`); while it is read the button reads "Stop reading". Voice behaviour is 3.11.
  - **Retry** (`retryTurn`): finds the user message the reply belongs to and calls `resendFrom` with its text. Disabled while a reply runs.
  - **Branch** (`branchAt`): calls `session.branch` with a message count so the new chat holds everything up to the end of this turn, renames it "⎇ <original title>" (a later branch of the same chat becomes "⎇ <title> 2", and so on, because Hermes wants unique titles), opens it, and toasts "Branched: <title>". Disabled while a reply runs. A branch of a chat that has read phone data (`chatReadState`, anything but a clear answer) is linked to it at once (`noteLineage`), so the page's guards cover it from the first moment: it holds the messages but not the `phone_data` call.
  - **Stats** text such as `~41 tok/s · 1m 23s`: tokens per second (from the provider's `avg_tps`, else estimated from the stream, else from the turn's wall time) and the turn's duration (`fmtDuration` in `text.ts`, shown when the turn took at least 1 s). The context fill is the ring in the composer (3.4), not part of this text; stats saved by older builds end in `ctx 2% · 8k/200k`, which `stripCtxStat` removes when they are shown. Saved per turn in `hm.stats.v1` (2000 entries), so it returns when the chat is reopened.
- **Time.** Tapping the reply (not on a link or control) shows its time, like a user bubble (not while streaming).

Actions are not drawn on earlier segments of a turn (a reply split by tool calls), on streaming replies, or in a preview.

#### Retry, edit and undo: what they do on Hermes's side

`resendFrom(itemId, text, images, files)` in `web/src/gateway.ts`:

1. Over the lock screen, whatever the chat's access, asks for an unlock and sends nothing ("Unlock the phone to use this chat", the words `sendPrompt` uses): it starts a turn and drops the later ones from Hermes's history, which talking there doesn't. Checked again right before each `prompt.submit`, since the phone can lock while the row and photos are looked up. The Edit and Retry buttons aren't shown over the lock screen (`useLocked` in `ChatItems.tsx`), and an edit box left open closes.
2. Refuses while a reply runs ("Wait for the current reply to finish").
3. Finds the user message's durable row id (`userRowId`: the item's `rowId`, else read from `session.history` by position from the end).
4. Replaces the view from that message onward with the new user message and starts "running".
5. Re-queues the message's photos with `image.attach` (Hermes queued them for the original turn only). Files travel as their `@file:` references in front of the text.
6. Calls `prompt.submit` with `truncate_before_row_id` and `confirm_truncate`. Editing the very first message also sets `confirm_empty_truncate`.
7. If Hermes says the row is "no longer in session history" and it was the last turn (a failed last turn is stored but never entered the live history), it sends the text as a normal prompt. Otherwise it fails with "That message isn't in this chat's history any more. Start a new chat to begin again".
8. On any failure it takes the photos back out of Hermes's queue (`image.detach`), reloads the chat from Hermes (`resumeSession`) and toasts "Send failed: <reason>".

**Undo last turn** (chat menu, 3.5) calls `session.undo`, reloads the chat and toasts "Last turn undone". It is disabled while a reply runs.

#### Tool card

`ToolCard`. One card per tool call, collapsed by default.
- **`phone_data` cards are plain text:** the arguments and the result of a `phone_data` call (the user's own messages, which can carry a web address) are shown as text only: no media preview (nothing is fetched when the card opens) and no link; other tools are unchanged.
- **Chats that have read phone data (`phone-data-taint.ts`).** When the chat's items hold a `phone_data` tool call (any outcome; derived from the items, so it comes back after a reload or a resume, and it covers replies already drawn when the read happens), `AssistantMsg` and the /btw answers pass `guard` to `Markdown`, which sets `GuardCtx` for what is inside. This holds in every access mode, Full access included; chats with no such call are unchanged except for the next sentence and the Mermaid one below, which hold in every chat, guarded or not (a remote image's address can carry out what the agent has read, and a prompt injection can write one): a remote (`http`, `https` or `//`) image, video or audio is not fetched; `Media` (which no longer reads the guard for this) shows a `.remote-hold` button with the host name and "Tap to load" (`RemoteHold`), and loads only after the tap (a pointer drag/scroll across the button is ignored, the hold state is keyed to `src`, and a remote image that fails to load returns to `RemoteHold` showing "Couldn't load · Tap to load" with its host and query warning instead of becoming a `FileChip`). Local files, attachments and `data:` or `blob:` sources load as before. A video card (`VideoPlayer`) shows no thumbnail, and its play button shows the address in the "Open this address?" dialog and opens it in the browser (a player in the page would need requests the shell refuses). The placeholder also says "has data in the address" (`.remote-hold-data`) when the address has a query. An image's tap calls `allowRemoteOnce` (the shell lets exactly that address through once, 4.5), then loads it immediately (without `loading="lazy"`, so the single-use allowance is used while fresh); an audio or video placeholder says "Tap to open" and opens the address through the same dialog, because a player makes several requests. The guard is read with `useGuard` (the Markdown context, else the chat on screen), so it also covers places with no Markdown around: tool cards (a URL in a tool's output), notices (`Markdown` also reads `useTainted` itself, so system rows and the canvas are covered), `Linked` text (reasoning, tool arguments, a subagent's goal: its links open through the dialog), and the canvas's `HtmlFrame` (no network even with the Online switch on). In the Markdown, `rehypeTaintStrip` (after `rehype-sanitize`, which stays in front) removes `picture`, `source` and every `srcset`. A Mermaid diagram that would load an image (`MERMAID_IMAGE`: an `img:` shape, `<img`, `url(`) is not drawn but shown as code with "mermaid (not drawn: it names an image or an address)", in every chat; a diagram with only links or addresses in its text is drawn. In a chat that has read phone data the wider `MERMAID_REMOTE` applies (`img`, `<img`, `http(s)://`, `//`, `url(`, `href`). A chat also counts as having read phone data when a subagent's own tool event names `phone_data` (`phoneData` on its item, set in `gateway.ts`); a subagent that never did changes nothing, and a reloaded chat's subagent rows carry no tool names, so the plugin's record is what remains there. Every link to the web (`ExtLink` for links and inline-code addresses, `FileChip` and the lightbox's "Open with…" for remote files, the "Open" button of a video card, links tapped inside an HTML preview, and a card's `@OpenUrl`) goes through `openChecked`: a dialog (`web/src/dialog.tsx`) titled "Open this address?" lists "Site: <host>", "Address: <the full address>" and, when there is one, "Data in the address: <the query>", and opens only on Open; Cancel opens nothing.

- **Header (tap to expand):** a drawn icon for the tool (`TOOL_ICONS` maps the tool's name to an icon name: terminal, play for execute_code, file for read_file, pencil for write_file and patch, search for search_files, globe for web_search and web_extract, compass for browser_navigate, sparkles for skills, brain for memory, checklist for todo, subagent for delegate_task, help for clarify, eye for vision_analyze, palette for image_generate, mail for send_message, phone for phone_app, a wrench for anything else), a title in plain words, a label, and a state mark.
- **Title** (`toolTitle` in `web/src/toolsay.ts`, see `docs/research/chat-tool-visuals.md`): words that follow the state. `terminal`: "Running git" / "Ran git" / "Failed git" (the program from `programName`, "a command" when there is none); `execute_code`: "Running code" / "Ran code" / "Code failed"; `read_file`: "Reading" / "Read" / "Couldn't read"; `write_file`: "Writing" / "Wrote"; `patch`: "Editing" / "Edited"; `search_files`: "Searching" / "Searched"; `web_search`: "Searching the web" / "Searched the web"; `web_extract`: "Reading the page" / "Read the page"; `browser_navigate`: "Opening" / "Opened"; `todo` and `todo_list`: "Updating tasks" / "Updated tasks". Other tools show their own name. The raw name is the title's tooltip and, when the open card shows arguments, sits next to "Arguments" (`.tool-raw`).
- **Label:** the tool's own context line, else for `phone_app` a plain sentence ("Using Keep", "Tapping in Keep", `phoneAppLabel` in `text.ts`), else for `terminal` the command without its shell wrapper (`commandLabel` / `commandText`: `bash -lc '…'`, `sudo` and leading `VAR=value` removed), else the first of `command`, `path`, `query`, `url`, `name`, `goal` from the arguments.
- **State mark:** spinner while `generating` or `running`; when done a green tick followed by the duration (`850ms`, `3.2s`, `1m 5s`), or the tick alone (read to screen readers as "done") when there is no duration; a red cross on error (read as "failed"). Both are `DrawnMark`: a step seen running draws its mark once as it ends, and the running step's words shimmer (3.2 Agent motion).
- **Task lists:** a `todo` / `todo_list` call (`todoSteps`: the `todos` of its result, else of its arguments) has the label "N/M done" and, open, its steps as a list (`.tool-steps`) with the marks of `stepMark` (✓ done, ◐ in progress, ✕ cancelled, ○ to do; the status bar's task list uses the same marks) instead of the Arguments and Output JSON.
- **Risk:** a tool flagged by Hermes (`tool.output_risk`) gets a red outline and, expanded, a "⚠ <reason>" note.
- **Opening and closing:** the body is wrapped in `Collapse` (`ui.tsx`), so it slides open and closed in 180 ms (see Motion in 3.20). After a tap that closes it, the body stays mounted until the animation ends.
- **Expanded body**, in order: Arguments (JSON; the noisy file body and replaced strings are left out when a diff is shown), Summary, Diff (Hermes's inline diff, or a diff built from the `memory` tool's arguments, or a diff found in the result), any image / video / audio path or URL found in the output (drawn with `Media`), Output (readable part of a JSON result, with `exit N` and error in the caption, a Copy button, cut at 20,000 characters).
- **Stored output.** A tool card restored from history has no result text. When opened, the card fetches it from the plugin (`GET /tool-result?id=<tool call id>`), shows "Loading output…", caches it, and says "No output recorded" if there is none. Cards with a locally made id are not fetched.
- **Folding.** `web/src/fold.ts` `toolRuns` finds runs of at least three tool cards with only tool cards and reasoning-only replies between them. A closed run is one line (`ToolRunHead`): up to four tool icons, what the calls did in words and their summed time, such as "Ran 2 commands and read 3 files · 42s" (`runLabel` with the run's `summary` from `runSummary`: commands, edited files (counted once per path), read files, searches, web and browser use, task updates, other tools; when there are more than three kinds, the first two by name and the rest as "used N other tools"), or "Running 4 tools…" while one runs, " · N failed" when some failed, the list of tool names, a spinner while one runs, and a chevron. Tap toggles the run (keyed by its first item's id). A run still working keeps its last card visible. Every item keeps its own element in the list, folded ones as empty placeholders, so message search can find them by position.
- **A finished turn folds into one line** (`web/src/turnfold.ts`, decision 2026-11-16 in the redesign brief: the answer is what the screen is for). `turnWorks` finds, in each turn (a user message and what follows up to the next), the final answer (the last reply with text) and the work before it: tool cards, folded runs, sub-agent groups, reasoning-only parts and earlier reply parts. What a person acts on stays outside and keeps showing: notices, `canvas` and `image_generate` cards (`KEEP_TOOLS`), and reply parts with a card, a picture, a `MEDIA:` path or a file link (`KEEPS`); the changed-files card keeps its place after the turn's last item. A turn is left as it is while it runs (the last turn while `running`), while any of its steps still runs (a tool, or a detached sub-agent: `isLive`), without a final answer, or when its work would be a single line and the answer has no thought. Each `TurnWork` has its key (the user message's id), the first work item (`head`), the hidden `members`, the `final` answer, `steps` (tool calls and sub-agents), `failed` (tools in the error state, sub-agents failed or timed out: `wentWrong`) and the first of them (`firstFailed`), its length in seconds and the tool names. The length comes from the stats under the answer (`metaSecs` reads the duration at the end of `meta`), else from the user message's and the answer's times, else from the summed tool durations.
  - **The line** (`TurnWorkHead`, a button with `aria-expanded`): up to four tool icons, "Worked 1m 20s · 14 steps" (`workLabel`; "Worked through 3 steps" when nothing says how long), " · 1 failed" in `--err` (`.turn-work-err`) when a step failed, and a chevron. It sits in the head item's element (`.turn-work-wrap`); the other members are empty placeholders (`.folded`, or `.turn-end` when they carry a card or the "New Messages" divider), so every item keeps its child index. The final answer is drawn with `quiet`, so its thought joins the line.
  - **A tap** opens the turn to exactly what it showed before (runs and sub-agent groups with their own lines, closed or open as they were); what appears arrives with the shared row movement (`.turn-reveal`, `motion-row` in `motion.css`, nothing under Off). Another tap closes it. A turn with a failed step opens with that step brought to 8 px under the top bar, the run that holds it opened first. The choice is kept per turn (`TurnChoice`, in the chat view's state) while the chat stays open and forgotten when another chat opens, so every finished turn is closed again the next time.
  - **A turn that finishes on screen** is first drawn as it was while it ran (`settling`). Before the screen is painted, the chat looks at its lowest work that takes room: when that is above what the reader sees, the turn folds and the answer's text keeps its place (a reader at the end stays at the end); otherwise folding would move visible text, so it is left as it was (`later`: no line) until the chat is next opened.
  - **How each index draws** (`turnFoldMap`, giving `TurnFolds`): `heads` (the line and whether it is open), `hidden`, `quiet` (answers whose thought is in a closed line) and `byIndex` (the turn each index belongs to). Message search, in-chat search and the scrubber open a closed turn that holds their target first (`unfold`), then a run inside it, then scroll as before. Shared Markdown (`export.ts`) and read-aloud are unchanged.

#### Sub-agents

Decision: [nested-chats.md](../decisions/nested-chats.md). Code: `web/src/subagents.ts` (records, grouping, words), `web/src/components/SubAgentsCore.tsx` and `web/src/subagents-core.css` (the group's line), and the lazy bundle `hm-subagents` with the rows and the sheet: `web/src/components/SubAgents.tsx`, `web/src/subagents-view.ts`, `web/src/subagents.css` (2.6). It loads when the group's line first shows, so a chat without sub-agents costs nothing.

**The group** (`subGroups`, `subFoldMap`, `SubGroupHead`). Sub-agent items next to each other are one group, and one started by a member joins that group wherever it stands. Closed it is one line: "3 sub-agents · 1 done" while they run (with the working shimmer, on the newest running group only, under Full animations), "Used 3 sub-agents · 2 min" when all have ended (`groupWords`). A failed or timed-out one adds "· 1 failed" in `--err`, also folded. A tap opens it: over the lock screen it asks for an unlock instead.

**A row** (`SubRow`, drawn only while the group is open): a state mark, the goal, the model's short name and the level in dim text ("haiku · low", `runsOn`, the composer chip's short forms, a long name cut so the level stays), and the state word: Waiting, Failed, Timed out, Stopped, or Finished when the app only knows it has ended; Working and Done are said by the mark, and read by screen readers (`STATE_WORD`, `stateOf`). Nested ones stand under their parent, indented (`inTreeOrder`: by `parent_id` or the stored chat, else `depth`). The current step shows under one that runs. A tap opens its sheet.

**The sheet** (`SubAgentSheet`, `aria-label` "Sub-agent"; store `sheet: 'subagent'`, `openSubSheet`, `subSheetChat`, inside `SheetBoundary`, so a failure stays in the sheet). Each sub-agent has its own copy of the content, so a draft never carries over. One size, moved: it rests at about half the screen and is pulled up to just under the chat's header; pulled down it returns to half, then closes. Android Back closes it, or goes back one step. It closes if the app shows over the lock screen (`lockview.ts`) or whenever the chat on screen changes away from the sheet's chat (`resumeSession`, `startDraft`, `newSession`, `switchProfile`, `deleteSession`, and in `SubAgentSheet` itself).

- **Head:** the goal; "Sub-agent of <chat title>" (a nested one: of its parent's goal formatted with `quotedGoal` inside `<bdi>`), the state, the time.
- **Model and Reasoning,** side by side, first under the head. The level comes from the sub-agent's stored chat (`GET /nested`, or `GET /api/sessions/{id}` with an older plugin, tried a few times while the row appears): `effortWord` gives Off, Minimal, Low, Medium, High, Extra high, Max, Ultra, or "Model default"; until it is read "Checking…", then "Not reported". It is never worked out from settings. "· same as the chat" shows when `delegation.reasoning_effort` sets nothing and the level equals the chat's (`followsChat`).
- **Numbers:** steps, tokens in and out, files read and written (`numbersLine`).
- **What it is doing** (`aria-label` "What it is doing"): while it runs, `subagent.tail` as plain text without the transcript's header (`tailText`), at most every 3 s (`TAIL_EVERY_MS`), one call at a time, only while this sheet is open, it runs and the app is on screen. **What it did** (`aria-label` "What it did"): its steps and summary, from the event and `GET /api/sessions/{id}/messages` (`storedSteps`), as plain text.
- **Its own sub-agents** (`aria-label` "Its own sub-agents"): rows as above; a tap replaces the content and a Back arrow returns.
- **Tell it something** (`aria-label` "Tell it something"): `subagent.steer`, shown while it takes messages; gone once Hermes refuses one.
- **Continue in a new chat,** for one that ended (`continueSubAgent`): offered only when the sheet's own chat (`chatTainted(chat)`) and the sub-agent have not read phone data (`idsReadState` is clear). Runs `session.resume` of its stored chat, `session.branch`, then opens that chat. It fails closed through `storedParentChain` (`GET /nested`, asked at the tap): refused unless Hermes's own record confirms the full parent chain from the sub-agent up through any parent sub-agents and verified compression segments (never branches), and unless `segments` is a non-empty list of at most 17 valid, distinct stored ids (`MAX_SEGMENTS`, the most the plugin sends) that starts with the chat and contains the end of the sub-agent's parent walk; a missing or empty `segments` (an older plugin, a failure) refuses rather than falling back to the chat alone. The new chat receives the lowest access across the default, any live runtime and every id in the real parent chain (and its lineage). It is a different chat: it is never put in the lineage group (`lineage.ts`) of the chat it came from or of any id in the chain, so a later read in it never marks the parent, and the parent's group never grows (its oldest ids are never pushed out). It starts clean because Continue is refused when anything in the chain read phone data. Refused before and after `session.resume` when the chat, any parent in the chain, the sub-agent or its stored messages read phone data or `idsReadState` cannot confirm clear. The check after `session.resume` reads the chat on screen again (its items may have changed during the wait) and first adds every id the answer names (`session_id`, `resumed`, `stored_session_id`, `info.stored_session_id`, and their lineage); the access is worked out after that, from all of them. `lockView()` is re-checked after each `await` (before `session.resume`, before `session.branch`, before renaming and before `resumeSession`). The group gives its rows the id of the chat whose items are drawn (`shownKey` in `chatview.ts`): while another chat opens with no copy of it on screen, the items are still the chat being left, and so is the id.
- **Sub-agent settings** opens Settings on Behaviour. **Stop** (red, last) asks first, then `subagent.interrupt`.

**Text.** Goals, steps, output and summaries are the model's: plain text, cut and cleaned of control and direction characters (`plainLine`). In the sheet the goal and the summary go through `Linked`, under a guard set from the sheet's own chat (`GuardCtx`, `chatTainted`), so an address in a chat that has read phone data is shown in full before it opens; the output and the steps have no links. Every event, list and stored row is checked by type (`mergeEvent`, `cleanStored`, `cleanNestedFeed`), so a malformed value can't break the page. A step or token change updates that sub-agent's record and its one row (`useSubAgent`), not the chat's items (`itemChanged`).

**What says a sub-agent runs.** Only `subagent.*` events and `subagent.list`. A record ends on `subagent.complete` or when `subagent.list` leaves it out (`noteRoster`); a saved item or a stored row never makes a running record. **Sync.** Once when a chat that has sub-agents or a `delegate_task` call opens, and when the app returns: `GET /nested`, `subagent.list`, then the items follow their records and missing ones go back in place (`withSubItems`), so no group keeps showing as running. No timer.

#### Notice

A box (`notice-info`, `notice-warn`, `notice-error`) with Markdown text. Where notices come from:

- **Info:** system rows of a stored chat; "Steer: <text>" after steering a running turn; results of slash commands (output of `slash.exec`, `/fast` status, `/yolo` result); "Context compressed: 80 → 21 messages"; Hermes's background review summary (`review.summary`); a finished background or side task whose result is not shown elsewhere.
- **Warn:** the `/yolo` on message, a command result that carries a warning.
- **Error:** "Send failed: <reason>"; a turn that ended with an error or failure reason (`message.complete`); a failed slash command ("/name: <reason>"); "/yolo: <reason>", "/fast: <reason>".

#### Markdown inside replies

`web/src/components/Markdown.tsx` `Markdown` renders replies and notices with `react-markdown`: GitHub-flavoured Markdown, math (KaTeX; `$…$`, `$$…$$`, `\(…\)`, `\[…\]`), syntax highlighting (KaTeX and highlight.js are loaded on the first message that needs them, `web/src/rich.ts`; until then a formula shows as its TeX and code without colours), raw HTML, and Obsidian-style extras. Before parsing, `prepare` (`web/src/text.ts`) rewrites a few things outside code: `MEDIA:<path>` lines become images or file links, `[[Note|alias]]` becomes plain text, `==text==` becomes a highlight, a leading `---` YAML block shows as a yaml code block, math fences and `\colorbox` are repaired, and blank lines inside balanced HTML blocks are removed so the block stays whole. `chatLinks` turns a bare session id (`20261029_101500_ab12cd`) into a link that opens that chat.

**A reply that arrives in pieces** (`web/src/mdsplit.ts`). Reading a whole reply as Markdown on every batch of streamed text, and colouring every code block again, was two thirds of the page's work during a long answer. `Markdown` therefore draws a streaming reply as a list of parts (`MdPart`, one `react-markdown` each, inside the one `.md` box, so the elements on the page are the same as for the whole text): `splitStream(prev, text)` returns the text cut at the start of top-level blocks, and a part whose text is unchanged is not read again. The rules, all decided by the Markdown parser (`unified` with `remark-parse` and the same extensions as the drawing, `REMARK`), not by blank lines:

- Only whole lines are looked at, and only a block that another block already follows is finished (a line still arriving can turn into something else).
- A finished part is at least 300 characters (`MIN_PART`) or stands before a block that long, and the next cut is looked for after 100 more characters.
- Before a cut is used, both sides are read alone and must give the same blocks as the text read as one; no part starts with an indented code block (the parser reads a list after one differently at the start of a text).
- A block with raw HTML (other than `<br>`), a task box or a link to a video stays in the last part with everything after it: HTML is read again as one document, task boxes are numbered and players counted per reply.
- A link or footnote definition (`[1]: https://…`) changes text anywhere, so that reply becomes one part again.
- When the text no longer starts with the finished parts (the reply was replaced), it is split from its start.

A reply that streamed stays in parts once complete (drawing it as one would build every code block, picture and frame anew); a reply opened from history is one part. Unit tests: `mdsplit.test.tsx` (the parts read alone equal the whole text at every step of a stream, also for random texts; the page of a streamed reply equals the page of the same reply drawn at once).

Rendering rules:

- **Safety.** Raw HTML goes through `rehype-sanitize` with an allow-list. Scripts, event handlers and unknown tags never get through. Inline SVG is allowed with presentation attributes only (no script, `foreignObject`, `use`, image or style elements). Inline `style` is cut down to looks (colour, spacing, borders, type); anything that positions, overlays, hides, or loads a URL is removed (a value may call only colour, arithmetic and gradient functions, and may hold no backslash or comment: `styleCanFetch`; an SVG attribute with a `url(` to anything but the page's own elements is dropped). A card with a background and no text colour gets a readable text colour chosen from the background's brightness.
- **Code blocks** (`CodeBlock`): a bar with the language (or "code"), then buttons Wrap (toggle line wrapping), Canvas (for blocks of 3+ lines: creates a canvas document of the right type, `html`, `svg`, `markdown`, `json`, `csv` or `code`, and toasts "Opened in the canvas"), and Copy ("Copied" for 1.2 s). Blocks over 26 lines are collapsed with a button "Show all N lines" / "Show less". An `html` or `svg` block of 3+ lines also gets **Preview** (before Canvas; label **Code** while the preview shows; disabled while the reply is still streaming, read from `StreamingCtx` so blocks aren't rebuilt per stream batch). In a chat that has read phone data (`useGuard`), any fenced `html` block (of any length) omits **Preview**, runs no frame, and displays the `.html-note` notice ("This chat has read data from your phone, so HTML previews are off here. The source is shown instead; nothing was run.") directly above its source. Preview replaces the code with the page in a sandboxed `HtmlFrame` (class `inline-frame`, always offline, see 3.7 "HTML runs in a sandbox"): it starts 160 px high and grows to the page's height, at most 60 % of the window height, then scrolls inside. `svg` shows as an `<img>` with a `data:image/svg+xml` source (no scripts). Below the frame a **Full screen** button (aria-label `Open preview full screen`) opens `HtmlViewer` (class `html-viewer`, `role="dialog"`, aria-label `HTML preview`, so swipe and pull gestures skip it; also `.inline-frame` is in their `SKIP` lists): the same offline page filling the screen, closed with ✕ (aria-label `Close preview`) or Android Back. "Show all" is hidden while previewing. A block tagged `diff` or `patch`, or an untagged block that looks like a unified diff, is drawn as a diff (below) without Wrap and Canvas.
- **Diagrams.** A `mermaid` block is drawn as SVG once Mermaid loads (about 250 ms after the text stops changing, theme follows light/dark, strict security level). Tap it (aria-label Open diagram full screen) to open the viewer: buttons Zoom out and Zoom in (steps of 1.35, range 50 % to 600 %), Fit, Copy (the source; toast "Diagram source copied"), and Close; pinch zooms, drag pans, Back closes. A diagram that cannot be drawn stays visible as code with the caption "mermaid (not rendered)".
- **Cards.** A block tagged `openui-lang` (or `openui`) is drawn by `OpenUIBlock` as an interactive card (3.9). If the card cannot be drawn, the source shows with the caption "openui-lang (not shown)". Card buttons can send messages only in chat replies (`interactive`), not in canvas, files or the By the way sheet.
- **Task lists.** `- [ ]` items get tap targets. The tick state is the user's: stored on the phone (`web/src/tasks.ts`, `hm.tasks.v1`, keyed by a hash of the message plus the box position, newest 300 messages kept) and it wins over the `[x]` the model wrote. Tapping the item's text ticks it too. The top-level list shows a bar and "N/M done".
- **Tables.** Tap a column heading to sort (numbers sort as numbers; tap again to reverse; a third tap restores the original order). Copy table copies a Markdown table (`tableMarkdown` in `text.ts`: `\` and `|` in a cell are escaped, line breaks become spaces).
- **Inline code and formulas.** Tap inline code to copy it (toast "Copied"); tap a formula to copy its LaTeX (toast "LaTeX copied"). Inline code that is only a web address opens it. Selecting text suppresses these taps.
- **Links.** Web links open with the phone's default handler (`openExternal` bridge call). `hermes-chat:<id>` links (and bare session ids) open that chat with a chat icon. `#footnote` links scroll inside the message. Links to local paths (`/`, `~/`, `file:`) become a file chip or inline media.
- **Images.** Markdown images are drawn with `Media`.
- **Videos.** Video links get a player in the chat (see Video player below).
- **Callouts.** `> [!note] Title` blockquotes become titled boxes; `-` or `+` after the type makes them collapsible (`+` starts open).

#### Media

`web/src/components/Media.tsx`. `Media` draws what a path or URL points to, by extension (`mediaKind` in `text.ts`: image, video, audio, or file).

- **Where the bytes come from.** `http(s)`, `data:` and `blob:` URLs are used as they are. A path on the phone is streamed in the phone app from the plugin's `GET /media` through the shell, with byte ranges so video can seek (`mediaBase` bridge call). Outside the app (desktop test browser) it is read through `GET /api/files/read` as a `data:` URL, up to 25 MB ("too large to show inline" beyond that). `~/` paths map to `/root/`.
- **Image:** lazy-loaded; tap opens the Lightbox. The Lightbox is full screen: pinch to zoom (1× to 6×), drag to pan when zoomed, double-tap to jump between 1× and 2.5×, buttons Save (to Pictures/Hermux; toast "Saved to Pictures/Hermux" or "Couldn't save the image"), Share, Open with…, and Close (✕). Tapping the dark area closes it at 1×. Back closes it. Outside the phone app, Save downloads the file and Share says "Sharing works in the phone app".
- **Video:** the browser's own controls.
- **Audio:** the app's own player: play/pause, a seek slider (aria-label Seek), elapsed and total time, and a speed button (aria-label Playback speed) that cycles 1×, 1.5×, 2×.
- **File chip:** `📎 name`; tap opens the file with the phone's default app (`openFile`; outside the app a toast says "Open works in the phone app").
- **Failures:** a file that cannot load becomes a chip with the reason in brackets. While loading it reads "Loading image…" (or video / audio).

#### Video player

`web/src/components/VideoEmbed.tsx` `VideoPlayer` plays a video inside the chat. Which addresses play, and each one's player address, is decided by `embedOf` in `web/src/videoembed.ts`.

- **What plays.** YouTube (`watch`, `youtu.be`, `shorts`, `live`, `embed`, playlists; the start time and playlist are kept), Vimeo, Dailymotion, Streamable and Loom through each site's own player page (YouTube's privacy address, `youtube-nocookie.com`), and a link to a video file through `Media`. Any other https page plays only when a reply asks for it with `<iframe src="https://…">` (`frameEmbed`); `<video src>` works the same way. Twitch and other sites that accept only named embedding pages stay ordinary links.
- **Where cards appear.** In anything drawn by `Markdown` (replies, the canvas, files, By the way), `rehypeVideoEmbeds` runs after the sanitizer on a finished reply and adds one card (the element `video-embed`, drawn by `VideoEmbedTag`) after the paragraph or list item holding a video link. A link that is its whole paragraph becomes the card; a link with its own words stays and the card follows it. A `MEDIA:` line or Markdown image with a video site address becomes a card too. Links in tables, headings and code stay links. Raw `iframe` and `video` tags pass the sanitizer with `src` only, and only to reach this step, which turns each into a card or removes it, so nothing the model writes loads a frame by itself. While a reply streams there are no cards yet. In your own bubble `VideoEmbeds` finds the links with `embedsInText`.
- **Limit.** At most three players per message (`MAX_VIDEOS`), without repeats; further links stay links.
- **The card.** 16:9, with the site's preview picture where it has one at a known address (YouTube; the picture does load from the site without a tap), a play button (aria-label "Play video from <source>") and a bar under it with the source's name and Open (aria-label "Open in <source>"), which stops the player and hands the address to the phone (`openExternal`). No player page loads until the tap.
- **Playing.** The tap swaps in the player's frame, autoplaying. Stop (aria-label "Stop video") goes back to the card. Starting a player stops the one before it (`stopCurrent`). Leaving the app (`visibilitychange` to hidden: home, another app, screen off) stops it too, since there would be sound with no way to stop it; the position is lost and coming back shows the card.
- **Fullscreen.** The player's own button; in the phone app see 4.1 (`enterFullscreen`).
- **The frame** is described in 2.3. In the phone app it goes through the shell's page (`frameSrc`, `EMBED_HOST`).

#### Diff view

`web/src/components/Diff.tsx` `DiffView` draws a unified diff in a monospace block: green added lines, red removed lines, blue `@@` hunk headers, bold file-header lines (`diff --git`, `index`, `---`, `+++`, `a/… → b/…`), yellow lines starting with `!`, and dim meta lines (`┊…`, `\ No newline`). ANSI colour codes from Hermes's terminal diffs are stripped, the "┊ review diff" marker line is dropped, and output over 20,000 characters ends with "… (truncated)". Web addresses in diff lines are links (`Linked`). `looksLikeDiff` decides whether plain text is a diff (a hunk or git header plus changed lines). The same view is used in tool cards, Markdown code blocks and the File checkpoints sheet.

#### Changed files card

`TurnChangesCard` (`web/src/components/Changes.tsx`, logic in `web/src/changes.ts`). When a turn (a user message and everything up to the next one) wrote files, a card follows its last item: "✎ 3 files changed" with the total `+A −B` (`.diffstat-add` green, `.diffstat-del` red; counts from 1000 shortened by `compactCount` to `1.2k`, `25k`, in tabular figures) and a chevron. Only `write_file` and `patch` tools (`EDIT_TOOLS`) that ended `done` count; failed ones, other tools and tools without `args.path` are ignored. The last turn gets no card while the reply is still running.

- **Tap the card head:** opens or closes the list: one `.turn-changes-row` per file (`shortPath`: `~/projects/site/a.txt`, long paths become `~/…/dir/name.ext`) with its own `+N −M`, then a **Checkpoints** button that opens the File checkpoints sheet (`sheet: 'rollback'`). A file edited several times is one row with the counts added up and the diffs joined in order (`diffCounts` counts `+`/`-` lines and skips `+++`/`---` headers; each file keeps at most `MAX_DIFF` = 200,000 characters of diff, then "… (truncated)").
- **Tap a file row:** a sheet titled with the full path showing `DiffView` of its diffs, or "No diff recorded for this edit". Back closes it.
- **Without a recorded diff** (older stored chats): `write_file` counts the lines of `args.content` as added and the row says "new or rewritten"; `patch` counts `old_string` lines as removed and `new_string` lines as added.
- **In the list:** the card shares one child element of `.chat` (`div.turn-end`, or the `tool-run-wrap` of a folded run) with the item it follows, so search, jump and the scrubber still find items by child index; it stays visible when the run is folded. Not part of exports or read-aloud.

#### Streaming

Events from Hermes (`client.onEvent` in `gateway.ts`) reach the chat for the open chat only:

- `message.start`: the turn starts (`turnStarted` in `turn.ts`); `running` is set and `turnStart` is set if the send didn't already (Hermes may send several per turn).
- `session.control.update`: the chat's goal changed (`control.goal`); the goal line follows it.
- `thinking.delta` / `status.update`: the status-bar text. A `status.update` that `quietStatus` (`quietstatus.ts`) matches is dropped: Hermes's "⚠ Auxiliary title generation failed: …" warning when the provider is busy (usually the title model's HTTP 429) would replace "Working…" for the rest of the turn, while the chat keeps the title it has and Hermes asks again on a later turn (Hermes patch 0004, 6.4).
- `reasoning.delta`, `message.delta`: appended to the open assistant item in batches (every 60 ms, every 150 ms once the reply is over 6000 characters), not per token, because every change reads Markdown again (the reply's last part, see "A reply that arrives in pieces"). Any other event flushes the batch first, so order never changes.
- `tool.generating`, `tool.start`, `tool.complete`: the tool card appears when the call starts being written, becomes `running` at `tool.start`, `done` at `tool.complete`. A tool that streams under a generic name takes its real name at start. A replayed start for a card that already exists adds no second card. Starting a tool closes the open assistant segment, so text after tools is a new segment.
- `todo.updated`, `session.usage` (also refreshes `ctx` without an RPC when the usage has `context_max` and `context_used`), `session.info`, `session.title`.
- `message.complete`: tool cards still "generating" are dropped; errors become a notice; the final text fills a reply whose stream missed some (`fullReply`); the turn stats are computed (`finishTurnStats`, given the turn's seconds read before `turnStart` is cleared); the turn ends (`endTurn`: `running` off, status text, speed and `turnStart` cleared; `failed` when it carried an error, else `done`). Live mode and automatic read-aloud (Settings or chat menu, when the app is on screen) speak the reply here.
- `review.summary`, `btw.complete`, `background.complete`: notices.
- A silent connection is checked: every 15 s `gateway.ping`; after 45 s without any event during a turn the page asks `session.resume` whether the turn is still running and loads the stored transcript if it finished meanwhile.

#### Loading a stored chat

`hydrate` (`store.ts`) turns Hermes's stored rows into items: user rows (with `@file:` and `@image:` references split off into attachment chips, and Hermes's "--- Attached Context ---" block dropped), assistant rows (text and reasoning), tool rows (with the stored inline diff), and system rows as info notices. Hidden rows are skipped, and a row id or tool call id seen twice is skipped (a resume of a chat that is still answering repeats its tail).
