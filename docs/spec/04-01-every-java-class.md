### 4.1 Every Java class

All sources are under `android/src/com/omarqaterge/hermesmobile` (package `com.omarqaterge.hermesmobile`), plus `bg/BgHost.java`, the phone-data readers in `phonedata/`, and `android/src/moe/shizuku/api/BinderContainer.java`. There are 30 source files in that package. They are plain `javac` code with no AndroidX.

| `AnswerBox` | The small answer box the question chip opens (4.3): the question, its choices and a text field, over the current screen. Hands the answer to `HermesService`. |
| `MainActivity` | The main activity. | `SttEngine` | One loaded sherpa-onnx speech model and the decoding around it, used by `LocalStt` (dictation) and `SttProbe` (checks). | `BgHost` | The background-app host. Owns one hidden virtual display and drives an app on it. Reads the screen through `UiAutomation` (subscribed only to the events that say a screen changed, used by `settle` to answer as soon as the hidden app stops changing: 200 ms after its last change, 500 ms when nothing changes, at most 1.5 s); no keyboard is shown on the hidden display (IME policy hide, local as the fallback). `scan`/`walk` number the elements, name rows with the text inside them (`folds`, `nameOf`) and leave keyboard windows out; `find` matches an element by its text; `node` refuses an element that left or changed. `frame` sends the last JPEG again while nothing new was drawn; `drawMarks` draws the numbers for `som` (with lines, `digit`: `app_process` has no font, and `drawText` crashes it); `allBlack` notices a secure (black) screen. | `main`, `handle`, `resolve`, `open`, `capture`, `scan`, `find`, `tap`, `swipeReq`, `setText`, `type`, `key`, `submit`, `toggle`, `scroll`, `scrollTo` (a list scroll that moves nothing is retried as a swipe), `waitFor`, `handOver`, `frame`, `settle` | The plugin's `phone_app` tool (over HTTP on loopback); `MainActivity.bgRequest` (frame, close, hand over) |

| `Contacts`, `Calendar`, `CallLog`, `Sms` | The read-only phone-data readers for contacts, calendar events, the call log and text messages, in `phonedata/`. Each checks its arguments first (unknown key, wrong type, text over `Caps.MAX_QUERY`, reversed or over-long range, unknown box: `IllegalArgumentException`), then runs one parameterised `ContentResolver` query, stops at the row cap and caps the whole result with `Caps.fit`; `truncated` is true when another row exists or any text, list or the size cap cut something. `Sms` with a phone-number sender narrows on its last 7 digits and confirms with `PhoneNumberUtils.compare` within a bounded scan (500 rows); other senders are a substring match. `Contacts` searches by name (LIKE with wildcards escaped) and fetches numbers and emails for all rows in two more queries; `Calendar` reads `CalendarContract.Instances` (window widened a day each side, filtered and sorted in memory, at most 500 instances scanned) so repeating events expand, soonest first, and all-day events are given at local midnight of their date; `CallLog` maps the call type to the contract's words; `Sms` reads inbox and sent only (no MMS, no attachments). A `SecurityException` from a missing permission is not caught. | `read` (static) | `PhoneData` |
| `Location`, `Photos` | The phone-data readers for location and latest photos, in `phonedata/`. They return no rows for now. | `read` (static) | `PhoneData` |
| `Result` | One reader's answer: `items`, and `truncated` when a cap cut rows off. | | the readers, `PhoneData` |

Support files that are not counted as classes:

- `android/src/moe/shizuku/api/BinderContainer.java` is a copy of the parcelable Shizuku's server wraps its binder in (Apache-2.0, RikkaApps). The class name is part of the wire format, so it must keep that package. `ShizukuProvider.call` reads it.
- `android/res/values/strings.xml`: `app_name` is `Hermux`; `sc_new` New chat; `sc_live` Live mode; `sc_live_long` Talk to Hermux (Live mode).
- `android/res/values/styles.xml`: theme `HermesTheme` (Material, no action bar, window/status/navigation bar colour `bg` = `#0E1115`) and the colours `bg`, `gold` (`#D9A441`), `icon_bg` (`#0E1115`, the launcher icon's background).
- `android/res/drawable/ic_stat_hermes.xml` (the small notification icon) and `ic_stat_shield.xml` (the approval chip icon).
- `android/res/mipmap-*/ic_launcher_fg.png` and `mipmap-anydpi-v26/ic_launcher.xml`: adaptive launcher icon: the `icon_bg` near-black background, a gold caduceus between two arrows (`> <`) as the foreground, and the same image as the monochrome (themed icon) layer. The gaps between feathers and serpents are transparent, so a themed icon keeps the detail. The mark stays inside the central 66 dp of the 108 dp canvas, clear of launcher masks. `android/icon/hermux-icon.svg` is the source; `tools/icon/make-icon.cjs` draws it and renders the five PNG sizes (`node tools/icon/make-icon.cjs --png` re-renders from the SVG); without `--png` it also writes `web/src/components/hermux-mark.ts` for the empty chat screen (3.2).
- `android/res/xml/shortcuts.xml`: launcher shortcuts New chat and Live mode (4.6).
- `android/res/xml/network_security_config.xml`: cleartext traffic is off except to `127.0.0.1` and `localhost` (the on-device Hermes). Everything else must be TLS.
- `android/assets/www/index.html` is the built web UI and `android/assets/phone/uninstall.sh` is the copy of `phone/uninstall.sh` that `Uninstall` runs; `android/assets/phone/plugin-update.sh`, `plugin.tgz` and `plugin.txt` are what `PluginSync` installs (6.6); all are copied in by `build.sh`.
