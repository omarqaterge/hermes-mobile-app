### 7.5 Versioning and releases

- **Version name** `a.b.c` (for example `0.8.62`) is shown in Settings → About and read by the app with `appVersion`. `web/src/update.ts` `isNewer` compares dotted numbers part by part (a leading `v` is ignored; non-numbers count as 0).
- **versionCode = a*10000 + b*100 + c**. `0.8.62` gives `862`. The number must stay above every earlier build's code (the rule in this project is that it stays above `821`), because Android refuses to install a lower code over a higher one, and `MainActivity` refuses a downloaded update whose `versionCode` is not higher than the installed one ("You already have this version.").
- **Local builds** pass both values to `android/build.sh` (`VERSION_NAME=… VERSION_CODE=…`) and are signed with the local keystore; a phone can only update from a build signed with the same key.
- **Releases** are made by pushing a tag `v*` (for example `v0.8.62`) to `main`, or on GitHub's website (Releases → Draft a new release, a new `v*` tag on `main`, Publish release). `release.yml` builds and signs the APK and attaches `hermes-mobile.apk` to the GitHub release. The signing keystore is the repository secret `KEYSTORE_B64` (base64 of the keystore file). `releases/latest` is what the in-app update (Settings → About), `UpdateNotice` and the installers (`phone/install.sh`, `setup-phone.sh`, `setup-phone.ps1`) download.
- **Changelog fragments.** A change users notice gets its own file `changes/YYYY-MM-DD-short-name.md` holding its CHANGELOG bullets (`changes/README.md` says how), not a line at the top of `CHANGELOG.md`: branches worked on in parallel then never conflict over the changelog. Before tagging, the maintainer runs `python3 tools/changelog.py release vX.Y.Z`, which moves the fragments (newest first) and anything still under `## Unreleased` into the new release section and deletes the fragments; that commit is the release notes.
- **`CHANGELOG.md`** has an `## Unreleased` section on top (entries written before the fragments, until the next release folds them); each release section `## vX.Y.Z (date)` collects what shipped since the previous tag, user-facing wording, with a line saying what was tested on which device. Released versions are not always consecutive tags (some build numbers were never tagged).
- The ready-made Debian image has its own release tag, `hermes-image-<pin12>` (7.4), never "latest".
