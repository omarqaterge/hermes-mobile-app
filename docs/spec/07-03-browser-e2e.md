### 7.3 Browser e2e (`tools/web-e2e/`)

Headless Chromium drives the built web UI against a mock Hermes, with no phone. It is the check to extend for every web change; it does not replace a test on a device.

| File | What it is |
|---|---|
| `run.sh` | Entry point. Installs `node_modules` if missing, picks `$CHROMIUM` (or a Playwright browser under `/opt/pw-browsers`), runs `npm run build` in `web/` (skipped with `HM_E2E_SKIP_BUILD=1` when `web/dist` is already built, as in CI), starts `mock.cjs` (port 9119) and `web/devserver.py` (port 5180), waits until each prints that it listens (`mock on <port>`, `devserver on <url>`; up to 10 s), runs `test.cjs` (and through it `checks/*.cjs`), stops both on exit (both exit quietly on `SIGTERM`). When 9119 or 5180 is taken (another run, an `adb forward tcp:9119` to the phone) it picks free ports and says so; when one is taken between that check and the server's start (two runs started at the same moment), that server exits and `run.sh` starts both again on ports the system picks (three tries), so a run never talks to another run's mock or page; `HM_E2E_MOCK_PORT` / `HM_E2E_WEB_PORT` choose them, and it passes them on to the mock, the page server and the tests. Each run writes its own call log (`HM_E2E_LOG` in a temporary folder removed at the end), so runs at the same time never mix. On a Mac without Playwright's browser it uses Google Chrome. `run.sh --serve` runs no tests: after the build and both servers are up it prints `run.sh: page http://127.0.0.1:PORT (mock Hermes on PORT)` and keeps them running until Ctrl-C or a kill, so a change can be tried by hand or by an agent's browser without a phone (`docs/verification.md`). |

**Mock contract check (`tools/hermes-contract/`, CI job `hermes-contract`)**: the browser tests prove the app works against `mock.cjs`, not against Hermes; this check keeps the mock honest. It starts the pinned Hermes for real and sends it and the mock the same requests, then compares the reply shapes (keys and types, not values). A key the mock sends that Hermes lacks, or one of another type, fails; keys only Hermes sends are listed and allowed; a `null` on one side or an empty list is noted, not compared. An error on both sides fails too, unless the case expects that error (`expectError`): it would compare nothing. The Hermes runs the app's own plugin (`hermes-plugin/hermes-mobile`) and a fake local model, so the plugin's routes (reading and writing, in the throwaway home) and eight whole model turns (a tool call, an approval allowed and one denied, a question, a task list, file edits with their checkpoints, a sub-agent, a reply stopped while it streams) are compared too. No real model is called and no real key exists.

**`web/devserver.py`** (used by `run.sh`): serves `web/dist/index.html` on `127.0.0.1:5180` (`HM_DEV_PORT` picks another port; `HM_HERMES_URL` another dashboard than `http://127.0.0.1:9119`), injects the Hermes session token into `sessionStorage` (the job the Android shell's bridge does; with the phone's key, `HM_EVENT_KEY`, only a verified dashboard's token, through `tools/devtoken.py`; without one, the page's token as served, which `run.sh` relies on by emptying `HM_EVENT_KEY` for the mock) and proxies `/__api/<path>` to the dashboard with the token. Prints `devserver on http://127.0.0.1:<port>` once it listens. Loopback only; the token never appears in a URL. For a manual run against the phone: `adb forward tcp:9119 tcp:9119`, `python3 web/devserver.py`, open `http://127.0.0.1:5180` at 375×812.
