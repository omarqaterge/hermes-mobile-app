# Trust boundaries

Hermes Mobile is local-first, but it still crosses a few important trust boundaries. This page is a compact reviewer checklist for those boundaries.

| Boundary | What crosses it | User control / note |
|---|---|---|
| Phone to model provider | Chat content and tool results needed for a reply | The user chooses the provider/profile: ChatGPT, Claude, Grok, Nous Portal, or an API-key provider. Provider terms still apply. |
| Android app to Hermes in Termux | Chat stream, status, approvals, files, canvas/media events | Local phone communication with Hermes on `127.0.0.1:9119` and the `tui_gateway` JSON-RPC connection. |
| Hermes to other Android apps | Screen reading, taps, and typing for app automation | Requires Android 14+ and Shizuku. Hermes asks once per app per chat; banking, payment, password, and 2FA apps stay off unless explicitly allowed. |
| Canvas HTML to network | Interactive pages/scenes generated by Hermes | Canvas HTML is sandboxed and offline unless the user allows network access. |
| Backups | Optional `Download/hermes-backup-<date>.tar.gz` archive | API keys and sign-ins are excluded unless the user explicitly includes them. |

## Notes

- The Android app, Termux/Debian runtime, Hermes Agent, and mobile plugin should be treated as one trusted phone installation.
- `adb forward tcp:9119 tcp:9119` deliberately exposes the local dashboard port to the attached computer while the forward is active.
- Cloud model use is not removed by the local-first design: selected providers receive the prompt and tool results required for replies.
- Setup scripts download packages and project code from public package repositories and GitHub; that install-time network access is separate from runtime model traffic.
- Memory writes are shown as diffs in the app, and the memory screen lets the user inspect what Hermes remembers.

## Update this page when changing

- network destinations or telemetry;
- model-provider or account flows;
- Android permissions, Shizuku use, or app-automation authority;
- canvas network defaults;
- API key, sign-in, memory, file, backup, or restore handling;
- local port binding or development forwarding instructions.
