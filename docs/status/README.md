# Status: what is going on

One file per workstream, so parallel branches never edit the same lines. Read the files here before you start, to see
what is in progress, what is blocked and what only a real phone can confirm.

- **Starting a workstream:** add `docs/status/<short-name>.md` in your first PR (what, why, the plan, what's done).
- **Moving it on:** edit only your workstream's file, in the same PR as the change.
- **Finishing:** delete the file in the PR that finishes it; what users notice goes in [changes/](../../changes/README.md).
- **Format:** a title, then **State**, **Next**, **Needs a real phone** and **Links**. Dates as YYYY-MM-DD.
- No personal data (phone models, paths, emails, IPs, chat contents): this repository is public.

Related: what was verified on a phone is in [docs/improvements.md](../improvements.md) and
[docs/manual-tests.md](../manual-tests.md); the owner's decisions are in [docs/decisions/](../decisions/README.md).
